Legacy search (manual fallback only)

Automatic discovery now runs off the Circle directory crawl (Communities tab → "Sync directory now"), not this web search — it stays only for the manual search-web/ search-watch CLI commands, so its settings aren't deleted, just no longer primary.

Search uses your Target roles above as the niches (plus a few skills). Add roles → they get searched.

Each lead scores 0–100. These are the points added when a signal is present, then the total is scaled by confidence:

What do these mean?
  • Hiring intent — the post is a real hiring request (not a job seeker). Every lead gets this.
  • Role match — its job title matches one of your Target roles.
  • Skill match — it mentions one of your Target skills.
  • Budget — it states a budget or rate ($20k, $50/hr).
  • Company — a company name was identified.
  • Recent — the post is recent (within the recency window).

The total is then scaled by classifier confidence. Priority: HIGH ≥ 80, MEDIUM ≥ 50, LOW below.

How it works — cloud scan with your session cookie

  1. Add each community host above (one row per community).
  2. Log into that community in your browser, and export its cookies (a cookie-export extension, or DevTools → Application → Cookies).
  3. Paste the cookie JSON into that community's “Add session cookie” box. You need both _circle_session and user_session_identifier — pasting the whole export captures them. Stored encrypted; never shown again.
  4. Press Scan now — the server reads your community over HTTPS and pulls leads. No browser needed after this; runs from the cloud.
  5. Each community needs its own cookie (Circle scopes sessions per community). Cookies expire — re-paste when a scan reports the session expired, and use Clear cookie to drop a dead one.
Requires CIRCLE_CRED_KEY set on the server (the cookie-encryption key). The older local connector (circle-connector) still works too, but this needs no local process.
